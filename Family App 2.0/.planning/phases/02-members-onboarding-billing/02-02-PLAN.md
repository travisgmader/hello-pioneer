<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → useTier derivation | UI gates premium features on a client-derived value |
| sessionStorage → actingAsId | Persisted acting-as context across refresh within a session |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-06 | Tampering | useTier() premium gate | accept | useTier is a UX convenience only; the authoritative gate is server-side — subscription_status is service_role-only (Plan 01 T-02-01) and RLS scopes all writes. A user editing client state to "premium" gains a sheet, not data access. |
| T-02-07 | Repudiation | acting-as audit (D-08) | mitigate | useOwnMember exposes the real actor's member_id for updated_by; useActingAs exposes the target member_id. Domain mutations in later phases write updated_by = ownMember.id, member_id = actingAsId, making acted-as actions queryable (updated_by != member_id). |
| T-02-08 | Information Disclosure | actingAsId in sessionStorage | accept | sessionStorage is origin-scoped and cleared on tab close; it stores a member UUID, not a secret. Session-scoping is the D-05 requirement, not a vulnerability. |
</threat_model>
