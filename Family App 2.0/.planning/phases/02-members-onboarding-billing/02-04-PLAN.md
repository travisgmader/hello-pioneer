<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → invite-member Edge Function | Untrusted caller requests a privileged email invite |
| invitee → claim_family_invite RPC | Untrusted user attempts to join a family with a code |
| service_role key | Must live only in the Edge Function environment, never in the bundle |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-12 | Information Disclosure | service_role key in client bundle | mitigate | inviteUserByEmail runs only in supabase/functions/invite-member; service_role read via Deno.env.get; never VITE_-prefixed; grep src/ clean (Task 1) |
| T-02-13 | Elevation of Privilege | invite-member caller authorization | mitigate | Function verifies auth.getUser then SELECTs the caller's member row and requires role='parent' before any admin write (Task 1, 401/403) |
| T-02-14 | Spoofing | code claim by unintended user | accept | Per RESEARCH Open Q3, MVP closed-family codes are generic; parent shares via private channel; one-time use + 7-day expiry bound exposure; Phase 7 can scope codes to a member |
| T-02-15 | Spoofing | replay of claimed code | mitigate | claim_family_invite (Plan 01) is atomic FOR UPDATE with used_at IS NULL check inside the transaction |
| T-02-16 | Tampering | email mismatch leaves orphan row | accept | handle_new_user matches lowercase email; mismatch falls back to the code-claim flow surfaced in InviteSheet ("send them the code instead") — documented MVP behavior (Pitfall 5/7) |
</threat_model>
