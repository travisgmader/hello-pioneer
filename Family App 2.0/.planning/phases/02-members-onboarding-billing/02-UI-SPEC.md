# Phase 2 — UI Design Contract

> Visual and interaction contract for Members, Onboarding & Billing. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Phase visible surface:** `/members` route (member card list + add-member FAB/CTA) → AddEditMemberSheet bottom sheet (name, emoji picker, color swatch picker, role toggle, "Under 13" toggle, `visible_sections` checkboxes) → CoppaConsentSheet (gated by "Under 13") → InviteSheet (6-digit code + email input, on un-linked member cards) → PremiumGateSheet (free-tier invite block) → AvatarChipRow (horizontal member chips above bottom nav) → ActingAsBanner (colored banner below TopNav) → `/join` route (code-claim form). Inherits the full Phase 1 design contract; this document extends it.

## Spacing Scale

Inherited unchanged from Phase 1 (multiples of 4 only).

| Token | Value | Usage in Phase 2 |
|-------|-------|------------------|
| xs | 4px | Member-card avatar-to-name gap, role-badge inner padding-y, focus-ring width, color-swatch ring offset |
| sm | 8px | Emoji-chip gap and color-swatch gap (matches `.emojiRow` gap=8px), gap between avatar chips in AvatarChipRow, error pill padding-y |
| md | 16px | MemberCard inner padding, default gap between form rows in AddEditMemberSheet, ActingAsBanner horizontal padding, `/join` form row gap |
| lg | 24px | Bottom-sheet content padding (top/sides), `/members` page outer padding, vertical rhythm between member cards |
| xl | 32px | Bottom-sheet content bottom padding (clears the drag handle + safe-area), gap between InviteSheet code block and email section |
| 2xl | 48px | Empty-state vertical breathing room above the "no members yet" illustration/copy on `/members` |
| 3xl | 64px | Bottom-nav height baseline; AvatarChipRow sits in the 56–64px strip immediately above it |

**Exceptions (documented):**

1. **44px minimum tappable target** — every interactive element (member-card edit/delete buttons, avatar chips, emoji chips, color swatches, role toggle, save/confirm CTAs, copy/share button) must satisfy `min-height: 44px` (or `min-width`/`min-height: 44px` for icon-only square buttons). Per WCAG 2.5.5 / Apple HIG; inherited Phase 1 convention.
2. **Avatar chip size** — circular chips in AvatarChipRow are `40px` diameter visual, wrapped in a 44px-min tap target. The 40px is a sizing constant, not a spacing token.
3. **Color swatch size** — color-picker swatches are `32px` diameter visual (8px grid), wrapped in a 44px-min tap target.
4. **`var(--radius)` = 16px (Lavender) / 4px (Midnight)** corner radius — theme-dependent, inherited. Bottom sheets use `--radius` on the top corners only; member cards use `--radius`; avatar chips and color swatches are fully round (`border-radius: 50%`, theme-independent).
5. **`env(safe-area-inset-bottom)` additive padding** on bottom sheets and the nav region — inherited Phase 1 rule.

## Typography

Inherited unchanged from Phase 1 — exactly 4 roles, exactly 2 weights. No new sizes or weights introduced.

| Role | Size | Weight | Line Height | Used For in Phase 2 |
|------|------|--------|-------------|---------------------|
| Body | 16px | 500 (medium) | 1.5 | Member name on cards, form field text, sheet body copy, COPPA consent summary, `/join` instructions, invite email field, banner "Acting as {Name}" text |
| Label | 14px | 500 (medium) | 1.4 | Form field labels, role badge ("Parent" / "Child"), `visible_sections` checkbox labels, "Premium" badge text, helper/error text, trial-days-left counter |
| Heading | 20px | 700 (bold) | 1.2 | Bottom-sheet titles ("Add member", "Invite", "Parental consent", "Premium required"), `/members` page H1 ("Family members"), `/join` H1 ("Join a family") |
| Display | 28px | 700 (bold) | 1.2 | The 6-digit invite code display in InviteSheet — the single display moment in Phase 2 (large, tracked, copy-friendly). |

**Heading font override (Midnight only):** `<h1>–<h4>` switch to `'Noto Serif', Georgia, serif`, `letter-spacing: -0.02em` (inherited).

**Disallowed in Phase 2:** font sizes other than 14 / 16 / 20 / 28; weights other than 500 and 700; italic; uppercase transforms. The 6-digit code may use `letter-spacing` + tabular/monospace numerals but stays at 28px / weight 700.

## Color

Both palettes are inherited verbatim from `src/theme/theme.css`. Phase 2 adds **per-member colors** (10-swatch palette) which are a NEW token category — they are member identity colors, NOT part of the 60/30/10 chrome split. The 60/30/10 split below describes app-chrome real estate.

### Lavender theme (default for light OS)

| Role | Value | Variable | Usage |
|------|-------|----------|-------|
| Dominant (60%) | `#fdf6ff` | `--bg` | `/members` page background, `/join` wrapper, bottom-sheet scrim is a darkened overlay over this |
| Secondary (30%) | `#ffffff` | `--card-bg` | Member cards, bottom-sheet surface, AvatarChipRow strip background, form inputs |
| Accent (10%) | `#c9a8e0` / `#9b7bbf` | `--lavender` / `--lavender-dark` | See "Accent reserved for" list below |
| Destructive | `#d4607a` text on `#fad4e0` bg | `--pink-dark` / `--pink-light` | Member-delete confirmation, expired/invalid-code error on `/join`, invite-send error pill |
| Text | `#3d2c4e` / `#8a7898` | `--text` / `--text-muted` | All non-accent text |
| Border | `#e8d5f5` | `--border` | Card outline, sheet handle, input border, chip-row top divider |

### Midnight theme (default for dark OS)

| Role | Value | Variable | Usage |
|------|-------|----------|-------|
| Dominant (60%) | `#0c0b0f` | `--bg` | Page background |
| Secondary (30%) | `#16141f` | `--card-bg` | Cards, sheet surface, frosted chip-row (`rgba(22,20,31,0.82)` + `blur(24px)` to match nav) |
| Accent (10%) | `#e9c176` (warm gold) | `--lavender` (re-mapped, name stays `--lavender`) | Same reserved-for list |
| Destructive | `#f9a8d4` text on `#1e0815` bg | `--pink-dark` / `--pink-light` | Same surfaces as Lavender |
| Text | `#e5e2e1` / `#8b8680` | `--text` / `--text-muted` | Warm off-white body, never pure white |
| Border | `rgba(233,193,118,0.12)` | `--border` | Ghost-gold hairlines |

### Member color palette (NEW — `src/lib/memberColors.ts`)

A static set of **10 distinguishable colors** mapped to existing theme tokens so they work in both Lavender and Midnight. A member's chosen color is applied as a CSS custom property (`style={{ '--member-color': color }}`) on their avatar chip, card avatar, and the ActingAsBanner background. These are member-identity colors and are **exempt from the 60/30/10 chrome split** — they appear only on member-scoped surfaces (avatar chip, card avatar dot, acting-as banner).

| # | Name | Token (light) | Notes |
|---|------|---------------|-------|
| 1 | Lavender | `var(--lavender)` | default for first parent |
| 2 | Mint | `var(--mint)` | |
| 3 | Yellow | `var(--yellow)` | |
| 4 | Pink | `var(--pink)` | distinct from `--pink-dark` destructive use |
| 5 | Blue | `var(--blue)` | |
| 6 | Peach | `var(--peach)` | |
| 7 | Lavender-dark | `var(--lavender-dark)` | deeper variant for contrast |
| 8 | Mint-dark | `var(--mint-dark)` | |
| 9 | Blue-dark | `var(--blue-dark)` | |
| 10 | Pink-dark | `var(--pink-dark)` | identity use only — never overlaps a destructive surface in the same view |

**Contrast rule:** member-color backgrounds carry the member's emoji (high-contrast against any swatch). Text never sits directly on a raw member color except the ActingAsBanner, which must render its label in a contrast-safe color — use white on the 6 mid/dark swatches and `--text` on the 4 light swatches, OR (simpler, recommended) overlay a `rgba(0,0,0,0.08)` tint + always-white label. Executor picks one and applies it consistently.

### Accent reserved for (both themes)

The chrome accent (`--lavender` / `--lavender-dark`) appears in **only** these Phase 2 surfaces:

1. **Active `/members` nav tab** — light-tint background + 2px upward translate (mobile), solid pill (desktop) — same as all other tabs.
2. **Active emoji chip** in AddEditMemberSheet — border `--lavender`, background `--lavender-light` (matches existing `.emojiChip[data-active]`).
3. **Selected color swatch ring** — the chosen swatch gets a 2px `--lavender` selection ring (the swatch fill itself is the member color).
4. **Role-toggle selected segment** (Parent / Child) — selected segment uses `--lavender` fill.
5. **Primary CTA buttons** — "Add member" / "Save member" / "Confirm" (COPPA) / "Join family" — solid `--lavender` background, white text (matches existing `.primary`).
6. **Form input focus ring** — `--lavender` outline (inherited input pattern).
7. **Active avatar chip ring** in AvatarChipRow — the currently acted-as chip gets a 2px `--lavender` ring (chip fill is the member's own color, the ring is the accent).

Accent is **never** applied to: member card backgrounds, the ActingAsBanner (which uses the member's own color), body copy, the "Premium" lock badge (uses `--text-muted` + a neutral lock), the invite-code display, or destructive surfaces.

## Interaction Contracts (Phase-2 specific)

These are required for the executor and ui-checker to validate behaviour.

| Surface | Interaction |
|---------|-------------|
| Bottom sheets (all) | `vaul` Drawer; open/close only — **no snap points** (RESEARCH Pitfall 8: snap points trap keyboard focus). Scrim darkens `--bg`; ESC + drag-down + scrim-tap all dismiss; focus trapped inside; body scroll locked. Top corners use `--radius`; a centered 36px×4px drag handle (`--border` color) sits at top. |
| `/members` nav tab | 7th tab, emoji 👥, label "Members". Hidden for any member whose `visible_sections` excludes `/members` (D-01). Active-state styling identical to other tabs. |
| AvatarChipRow | Horizontal-scroll strip mounted INSIDE `BottomNav`, ABOVE `.bottomBar` (D-04). One circular chip per member: member emoji on `--member-color` fill, 40px visual in 44px tap target, 8px gap. Active chip (= `actingAsId`) gets 2px `--lavender` ring. Tap a non-active chip → `setActingAs(memberId)`. Tap the active chip → navigate to that member's profile (route exists Phase 7; in Phase 2 it's a no-op or routes to `/members`). **Hidden entirely for non-parent roles** (RESEARCH Open Q5). Updates live via `useMembers()` realtime invalidation. |
| ActingAsBanner | Mounted as a SIBLING of TopNav, BEFORE `<main>` (RESEARCH Pitfall 3). `position: sticky; top: {topnav-height}; z-index: 150`. Background = active member's `--member-color`; label "Acting as {name}" in contrast-safe color; "Switch back" affordance on the right. Renders ONLY when `actingAsId !== ownMemberId`. Dismiss/switch-back sets `actingAsId` back to the parent's own member. |
| Member card | `--card-bg` surface, `--radius`, `--shadow`, 16px inner padding. Left: avatar (emoji on `--member-color` round dot). Middle: name (Body) + role badge (Label). Right: edit + delete icons (44px each). Un-linked cards (`auth_user_id === null` AND has `email` or is invitable) show an **Invite** action; if free-tier, that action shows the lock + "Premium" badge and opens PremiumGateSheet instead of InviteSheet. |
| Emoji picker | Reuse `.emojiRow` / `.emojiChip` pattern. Curated static grid (~24 emojis, `src/lib/memberEmojis.ts`) — NOT a full picker library (RESEARCH §Supporting). Selected chip uses existing `[data-active]` accent styling. |
| Color swatch picker | 10 round swatches (`src/lib/memberColors.ts`), 32px visual in 44px tap target, 8px gap, wrap. Each swatch fill = its member color; selected swatch gets a 2px `--lavender` ring + checkmark. |
| Role toggle | Two-segment control (Parent / Child); selected segment `--lavender` fill, white text; unselected `--card-bg` + `--text`. |
| `visible_sections` checkboxes | One checkbox per app section. All-checked persists as `[]` ("see all" default) — NOT the full enumerated array (RESEARCH Pattern 7 pitfall). |
| InviteSheet | Top: code section — 28px Display code, tracked, with **Copy code** (clipboard, label swaps to "Copied" 2s) and **Share code** (`navigator.share()` with clipboard fallback). Below a "or" divider: email input + **Send invite**. Both flows in one sheet (D-11). On free-tier this sheet is never reached — PremiumGateSheet opens instead. |
| PremiumGateSheet | Opened when a free-tier parent taps a locked Invite action (D-17). Title, body, **Upgrade** CTA → toast (no navigation, route doesn't exist yet — RESEARCH Open Q4). |
| `/join` route | Outside `RootLayout` (sibling of `create-family`). 6-digit numeric input, **Join family** → confirm step showing family name → **Yes, join**. Loading + expired-code error states. After claim, `current-family` query refetches and routes to `/dashboard`. |
| create-family link | A muted "Already invited? Join with a code" link routing to `/join` (RESEARCH Open Q1 — gives invited users a path in). |
| Trial counter | Surfaced on Dashboard and/or `/members` header (CONTEXT specifics). Label per copy table; uses `useTier().trialDaysLeft`; "Trial ends today" when `trialDaysLeft === 0 && trialActive`. |
| Optimistic CRUD | Add/edit/delete member follow the inherited TanStack Query optimistic pattern: list updates instantly, rolls back on error (no spinner on the happy path). |
