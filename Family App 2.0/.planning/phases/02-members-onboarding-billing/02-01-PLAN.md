<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| auth.users INSERT → members | New signup triggers privileged trigger that writes a public table |
| client → generate_invite_code/claim_family_invite RPC | Untrusted parent/invitee calls SECURITY DEFINER functions |
| authenticated role → family_settings columns | Parent can UPDATE settings but must not be able to grant themselves premium |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | family_settings.subscription_status | mitigate | revoke UPDATE from authenticated; grant only (timezone, theme, trial_ends_at, updated_by); only service_role (revenuecat-webhook) writes subscription_status (Task 3 step 7) |
| T-02-02 | Denial of Service | handle_new_user() trigger | mitigate | Trigger body wrapped in exception handler that RAISE WARNING and returns new — a trigger error can never block a Google signup (Task 3 step 4, Pitfall 2) |
| T-02-03 | Spoofing | family_invites code brute force | mitigate | 6-digit codes one-time use, 7-day expiry, claimed atomically via FOR UPDATE; used_at IS NULL checked inside the claim transaction (Task 3 steps 5-6) |
| T-02-04 | Information Disclosure | family_invites cross-family read | mitigate | RLS SELECT/INSERT policies gated on family_id = private.current_family_id() and private.auth_is_parent() (Task 3 step 3) |
| T-02-05 | Elevation of Privilege | generate_invite_code / claim_family_invite | mitigate | SECURITY DEFINER + set search_path = ''; generate guards caller is parent of p_family_id; claim derives identity from auth.uid()/auth.jwt() only (Task 3 steps 5-6) |
| T-02-SC | Tampering | npm install vaul | mitigate | slopcheck + blocking-human checkpoint (Task 1) verifying npmjs.com/package/vaul before install |
</threat_model>
